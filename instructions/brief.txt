Product brief — FTC Team App (scouting, team ops, robot & competition tools)

One-line: A cross-platform team app (mobile + web PWA) that centralizes roster & scheduling, parts and finance tracking, match scouting and analytics, and competition tools tailored to FIRST® Tech Challenge teams.

Executive summary

FTC teams need simple, reliable tools for people management, part inventory, scouting/strategy, and competition operations. This product bundles those needs into a single app built for use at practice, in the pits, and on the competition floor — with offline-first behavior, role-based permissions (students / mentors / parents), and integrations with FTC scoring (FTC-Live), Google Calendar, and common parts vendors. The app’s MVP focuses on roster + scheduling, basic scouting templates + analytics, parts inventory and purchase logs, and core match tools (timer, scoring simulator).

Suggested platform & architecture

Platform: Progressive Web App (PWA) + optional native wrappers (iOS & Android) for push reliability and native file access. Works offline, installs to home screen.

Backend: Serverless / managed (Firebase / Supabase) for realtime sync (Firestore / Realtime DB) and offline-first support. Use cloud functions to validate imports (schedule, scouting CSVs).

Database model (high-level):

Teams → Members, Roles, Permissions

Events → Matches, RSVPs, ImportedScheduleFiles

Inventory → Items, StockTransactions, Vendors

Scouting → MatchReports, Scouters, Templates

Finances → Transactions, Budgets, Orders

Media → Assets (with thumbnails, tags)

Integrations: Google Calendar (OAuth), FTC-Live/Scorekeeper CSV or JSON schedule import, optional FTP/CSV import from vendor purchase systems.

Authentication: OAuth (Google SSO) + email; guests via expiring links. Role checks via claims on JWT tokens.

Data & privacy considerations

Many users will be minors — minimize personal data stored (no unnecessary PII), require mentors to approve student signups, provide parental consent flows when required, and default to obfuscating contact details from other teams. Encrypt backups and use TLS in transit. Follow school and FIRST guidelines regarding student data.

User stories & acceptance criteria (examples)

As a scout, I want to scan a match QR and submit a match report in < 30 seconds so I can scout multiple matches. → Accept if median submission time ≤ 45s in dry run.

As a mentor, I want low-stock notifications when an item falls below threshold, so I can reorder before events. → Accept if push/email sent when quantity <= threshold.

As a drive coach, I want a countdown timer that vibrates at 10s, 5s, and 0 for driver cues. → Accept if audible/vibrate triggers reliably on-device offline.

KPIs / success metrics

Team retention (monthly active teams using app).

Avg time to submit a scouting form (goal: <60s).

Inventory accuracy (match physical counts vs. app counts; target >95%).

Reduction in mentor-admin hours per week (surveyed).

Increase in successful alliance picks (post-comp comparison) — long-term.

Risks & mitigations

Data privacy risk: store minimal PII; parental consent for minors and robust auth.

Offline sync conflicts: use last-writer-wins for non-critical fields, but for inventory/spend use optimistic locking & conflict resolution dialogs.

Rule changes each season: make scoring engine configurable by uploading the season rules or using a simple rules DSL so you can update scoring without code changes.
